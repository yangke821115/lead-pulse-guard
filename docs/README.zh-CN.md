## 为什么要使用线索监控器

### 你漏掉的线索，就是你丢失的利润

你花钱推广，客户也表示感兴趣 —— 但你还是可能错过他们的信息。

#### 🌐 网络访问受限制

不能 24 小时挂 VPN；频繁切换网络会导致账户被冻结；网络不稳定会让你收不到应用通知。

**解决办法**：申请接口，获得监控途径和所需的权限。

#### 🗣️ 语言不通，沟通受阻

潜在客户可能来自全球任何地方，就算主流语言也有数十种。如果你看不懂别人的留言，那就没办法做生意。

**解决办法**：接入 AI。它负责翻译、帮你分析并提供建议，让你只需要考虑如何给客户提供更好的产品与服务。

#### 🌙 我们要的是利润，不是熬夜

没人愿意 24 小时干活。我们都要双休，不要 996。

**解决办法**：部署线索监控器，把重复劳动交给它。

## 架构

### 多个线索来源，一个审批接口

所有渠道最终汇到同一张卡片：原始消息、模型草稿，以及一个可以「发送 / 改后发送 / 忽略」的按钮。

```
Facebook 评论 · feed
        │
        ▼
   Gateway  验证签名 · 打标签 · 去重
        │
        ▼
   Worker   知识库 · LLM · 起草回复
        │
        ▼
   人工审批   发送 / 改后发送 / 忽略
        │
        ▼
   Graph API   以主页身份发布
```

三条设计约束：

- **只读，零出站调用**
- **没有点击就不会发布**
- **交接靠文件，不走网络**

### 各入口如何防遗漏

| 入口 | 投递方式 | 防遗漏措施 |
|---|---|---|
| **主页评论** | webhook · feed | 自己的回复不推送 |
| **广告线索表单** | webhook · leadgen | 不相关的线索被过滤掉 |
| **邮箱** | IMAP 轮询 · 只读 | 主动轮询，保证不漏线索 |

> **我们实测过一天**：实际有 50 条广告线索，webhook 却只推送了 47 条。没有报错，没有日志，也没有重试 —— 从接收端看，链路断了和今天没线索来是一样的。
>
> 这就是为什么要使用线索监控器。

所以除了 webhook，还要对所有渠道做主动轮询。**轮询器不复制判断逻辑**：轮询会把线索重新签名、当成一条 webhook 送回网关，于是「要不要回复这条」只在一处存在。最坏情况从「永远收不到」变成「最多晚十分钟」。

## 包含什么

从需求到落地：一套考虑周全的自动化解决方案。以下每一项都在仓库里，设计理由写在 `docs` 中。

### ⌘ 对所有线索验签

对收到的原始线索计算 `X-Hub-Signature-256`，并用定时安全比较。签名不对的请求返回 403，且不记录内容。

### ⛔ 网关没有任何出站能力

它不持有任何下游凭据。即使被攻破，攻击者最多也只能往一个 spool 文件里写一行字。

### 📄 用文件，而不是消息队列

交接是一个只追加的 JSONL 文件。没有中间件要运维，每一条事件都能重放。

### 📚 按主页隔离的知识库

每个主页加载各自的「已确认事实」和「禁止表述」清单。知识库为空时，模型不得作出任何具体陈述。

### 🔍 输出自带检查项

输出是严格 JSON，带 `answers_question` 和 `invented_specifics` 两个自检字段。草稿有问题，在人工读到之前就能看出来。

### ⚡ AI 先分析

获得线索后先让 AI 分析，然后再推送给人工审核。

### 🔒 防止重复计数

webhook 和轮询会争抢同一个活动 ID：先到的占位，后到的自动变成空操作。

### ✉️ 邮件只读打开

全部用 `BODY.PEEK` 取信，不标已读、不移动、不删除。默认需要人工审核后才回复，也可以设置为 AI 自动回复。

## 快速开始

### 一行命令部署到你的服务器

> ⚠️ `AIW_POST_ENABLED=false` 时，点「发送」只会提示「模拟发送」，不会有任何内容发到 Facebook。**先看几条草稿，再考虑打开。**

```bash
# 1. 克隆并配置
git clone https://github.com/yangke821115/lead-pulse-guard.git
cd lead-pulse-guard
cp .env.example .env

# 2. 网关（验签 → 打标签 → 去重 → spool）
docker compose up -d gateway

# 3. Worker（spool → 知识库 → LLM → 审核卡片）
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
AIW_POST_ENABLED=false ./venv/bin/python -m worker.main
```

> **注意**：`feed` 和 `leadgen` 必须在**两个层级**都订阅 —— App 级和主页级。只配主页级看起来是对的，但什么都不会投递。

### 说说你现在每天收到多少条询盘？

两句话就够：**你卖什么、一天大概几条询盘、从哪几个入口进来**。

我们会告诉你值不值得上自动化 —— 包括答案是「不值得」的时候。

- 知识库审计 —— 哪些话绝对不能对外说
